# Foundry 13.351 / hyp3e 4.0.3 compatibility run

Date: 2026-08-14

Result: `PASS` through FND-006 and HUD-001/HUD-005

## Environment

- Foundry VTT: Windows Portable Build 13.351
- System: `hyp3e` 4.0.3
- Module: Hyp3e Utilities 0.1.0 from the working tree
- SocketLib: v1.1.4, used by the test-only diagnostic module
- Server runtime: Node.js 24.15.0
- Client: Codex in-app Chromium browser
- Client role: Gamemaster
- World: disposable copy of `hyp3e-test-fvtt-v13`

The test server used a workspace-local data root on port 33335. The portable
installation's original system and world databases and the Foundry 14 data
directory were not modified.

The ApplicationV2 diagnostic rendered three times: initial render,
action-triggered rerender with updated context, and explicit rerender. The same
application reference remained stable and closed cleanly.

The later foundation regression used an isolated server on port 33337. All six
foundation result groups passed, and the module published its adapter,
applications, compatibility result, and available SocketLib transport.

The HUD rule regression used isolated servers on ports 33347 and 33349.
HUD-001 through HUD-003 passed through the production module API with no
module-originated browser warning or error. Manual inspection confirmed that
the three card types were readable and hostile markup rendered only as text.

HUD-004 ran in a fresh disposable data root on port 33352. The production
controller passed every selection assertion against real canvas tokens and
reported no diagnostic error or module-originated browser warning or error.

HUD-005 ran in a fresh disposable data root on port 33354. UI actions produced
two reaction messages, two explicit Sorcery save messages, and one morale
message while reporting one missing-morale skip. Visual inspection confirmed
the overlay and responsive row layout at 1280 by 720. No unexpected
module-originated warning or error occurred.

HUD-006 ran in a fresh disposable data root on port 33356. The production HUD
passed centered-default, drag-handle, Pointer Event persistence, overlay
recreation, immediate reset, resize-clamping, and off-screen recovery checks.
The live setting retained `{left, top, width}` per client, and every HUD-006
diagnostic result was true with no diagnostic error.

HUD-007 ran in a fresh disposable data root on port 33358. Five rapid Actor
updates produced one model publication with the final HP value. Repeated
enable/disable, destroy/restart, and duplicate-start cycles retained one HUD
overlay, and every lifecycle assertion passed without a diagnostic error.

## Console and server observations

- No module-originated warning or exception was logged during activation,
  diagnostics, or deactivation.
- Foundry emitted its standard minimum-window-size warning because the
  automated browser viewport was 1280 by 720. HUD-006 explicitly measured that
  constrained viewport and remained within its 12-pixel safe margin.
- The server log showed successful license verification, world and compendium
  loading, creation and cleanup of synthetic diagnostic documents, and no
  stderr output.

## Cleanup

The isolated server was stopped and its disposable data root, copied license,
world, system, SocketLib copy, logs, and module junctions were permanently
removed. The portable v13 installation and its original test world remain
available for future compatibility testing.
