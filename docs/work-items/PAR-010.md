# PAR-010 — Prune deleted Party Actor references safely

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The active GM now owns one idempotent `deleteActor` lifecycle hook. When a
durable world Actor tracked as a member or follower is deleted, the hook sends
one named cleanup operation through the existing authenticated, serialized
Party mutation path. The operation removes the UUID from party membership,
follower employment, shares, and every marching-order rank.

The service also scans for unresolved member/follower references after Party
State initialization. Cleanup re-reads the current revision before each
request and retries bounded stale conflicts with a new request ID. Duplicate
hook delivery and already-pruned UUIDs are successful local no-ops that do not
advance Party State.

Synthetic/token Actors are ignored. The managed treasury UUID is deliberately
outside cleanup scope: deleting that Actor preserves its binding so the later
treasury recovery milestone can identify and recover the missing treasury
without silent recreation or destructive cascade behavior.

## Files changed

- `module/party/party-cleanup.mjs`: Adds strict payload validation, metadata
  pruning, active-GM hook lifecycle, missing-reference scan, and stale retry.
- `module/core/bootstrap.mjs`: Publishes the service, starts its hook once, and
  runs initial pruning after state initialization.
- `module/apps/foundation-applications.mjs`: Drops a local follower draft when
  external cleanup removes that follower.
- `tests/unit/party-cleanup.test.mjs`: Proves complete metadata removal,
  treasury/synthetic exclusion, one hook, initial scanning, and stale retry.
- `tests/unit/application-shell.test.mjs` and
  `tests/unit/compatibility.test.mjs`: Cover draft cleanup and API publication.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds the real Actor, synthetic
  token, and treasury deletion matrix.

## Verification

- `npm run check` passed with 98 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with `hyp3e` 4.0.3 and Foundry 14.365 with the official
  `hyp3e` dev 4.1.0 system each pruned a deleted member and follower with
  exactly one Party State revision per deletion.
- Shares, follower wage, and marching-order metadata disappeared with their
  tracked Actor. Deleting a real unlinked token and testing its synthetic
  Actor did not change state or remove the linked follower.
- Deleting the bound `treasure` Actor did not change the Party State revision
  and retained its exact treasury UUID through subsequent member/follower
  cleanup.
- The complete two-client Milestone 2 regression passed in both generations:
  permission policy, authenticated caller identity, duplicate suppression,
  concurrent stale rejection/retry, singleton UI, members, followers, row
  actions, local draft conflicts, and deleted-reference cleanup all remained
  green with no diagnostic errors.
- The 0.2.0 release-layout archive expanded into a clean module directory with
  the correct ID/version and every required runtime, style, language, license,
  and notice file; development tests were not bundled.

## Known limitations and follow-up

- Treasury resolution, rebinding, recreation, and duplicate selection remain
  assigned to TRY-001.
- Cleanup retries three stale conflicts and logs a warning if constant
  concurrent churn prevents a commit; ready-time pruning retries on reload.

No design-document change was required. No now-unused code remains.
