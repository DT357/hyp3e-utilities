# HUD-003 — Implement GM-whisper NPC roll chat cards

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

Added a shared chat-card service that consumes the immutable reaction, save,
and morale plans from HUD-001/HUD-002. It resolves the exact token or Actor,
evaluates one Foundry `Roll` per instruction, and creates one sequential chat
message per NPC with an attached Roll object and Foundry speaker attribution.

Every message uses Foundry-derived GM recipients and the supported private
message option for the active generation: `rollMode: "gmroll"` on Foundry 13
and `messageMode: "gm"` on Foundry 14. The service fails closed if the caller
is not a GM or Foundry returns no GM recipients.

Card content escapes all dynamic text. Namespaced flags record the feature,
action, save category, token UUID, Actor UUID, and shared batch ID. Skipped
targets and per-target failures are returned in one batch report and logged
once after processing.

## Files changed

- `module/chat/chat-cards.mjs`: Implements roll evaluation, target resolution,
  recipient handling, escaped card rendering, message creation, and batch
  reporting.
- `module/core/bootstrap.mjs`: Publishes the chat-card service on the module
  API.
- `lang/en.json`: Localizes action, result, save, and reaction labels.
- `styles/hyp3e-utilities.css`: Adds module-owned chat-card styling.
- `tests/unit/chat-cards.test.mjs`: Covers ordering, Roll attachment,
  generation-specific message modes, recipients, attribution, sanitization,
  flags, result evaluation, partial failure, and fail-closed privacy.
- `tests/foundry/diagnostics/diagnostics.mjs`: Creates and inspects live
  reaction, save, and morale messages.

## Verification

- `npm run check` passed with 39 automated tests.
- Foundry 13.351 / `hyp3e` 4.0.3 created four expected GM-only messages with
  evaluated Rolls, correct Actor/token speakers, stable token order, shared
  batch flags, escaped hostile markup, and rendered localized cards.
- Foundry 14.365 / official `hyp3e` dev 4.1.0 passed the same checks.
- Manual browser inspection confirmed readable cards for reaction, save, and
  morale results in both Foundry generations.

The first Foundry 14 execution exposed that v14 uses the `gm` message-mode key
instead of the v13 legacy `gmroll` key. The service correctly emitted no public
fallback messages. The mapping and unit test were corrected before the final
v14 run passed.
