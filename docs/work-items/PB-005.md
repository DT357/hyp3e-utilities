# PB-005 — Verify token-to-Actor identity behavior

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

Established token UUID as the HUD row identity. Linked tokens share a durable
Actor UUID; unlinked tokens expose token-scoped synthetic Actor UUIDs whose
writes remain isolated from the base Actor.

## Files changed

- `tests/foundry/diagnostics/diagnostics.mjs`: Added linked, duplicate,
  synthetic, update, selection, deletion, and cleanup checks.
- `HYP3E-UTILITIES-DESIGN.md`: Recorded the verified identity and update rules.
- `docs/compatibility-notes.md`: Recorded the compatibility contract.

## Automated verification

- `npm run check` syntax-checks the diagnostic module.

## Manual verification

- Two linked tokens resolved the same world Actor UUID.
- The unlinked token resolved a distinct token-scoped Actor UUID.
- A base Actor update propagated to both linked tokens and to the unlinked token
  before a synthetic override.
- A synthetic Actor update did not change the base Actor.
- Single, multiple, released, and deleted token states matched the expected
  live-canvas behavior.

## Known limitations and follow-up

- HUD-004 must use these findings when it implements row models and update
  subscriptions.
