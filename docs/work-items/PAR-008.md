# PAR-008 — Reuse Party Sheet ping, save, and morale actions

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Overview and Followers rows now ping placed tokens on the current scene and
offer the approved five-category save selector. NPC followers with numeric
morale also expose individual morale, and the Followers toolbar can roll all
eligible morale checks in one batch.

The Party action service delegates unchanged targets to the existing
`npcRolls` save/morale planners and sends their batches through the existing
GM-whisper chat-card service. It contains no copied system roll formulas,
comparisons, or chat rendering. Roll controls are GM-only and the service fails
closed when invoked by a player or when a planner returns no eligible rolls.

Token ping prefers a matching controlled token, otherwise uses stable token
document-ID order, and calls Foundry's shared `canvas.ping` API. A missing
canvas token causes no ping and one localized notice.

## Files changed

- `module/party/party-actions.mjs`: Adds deterministic token resolution and
  thin save/morale delegation with GM and availability guards.
- `module/party/party-members.mjs` and
  `module/party/party-followers.mjs`: Add row action capabilities derived from
  the hyp3e adapter.
- `module/apps/foundation-applications.mjs`: Adds ping, category-specific save,
  individual morale, and bulk morale actions with localized failure handling.
- `module/core/bootstrap.mjs`: Publishes and injects the Party action service.
- `templates/party-sheet.hbs`, `styles/hyp3e-utilities.css`, and
  `lang/en.json`: Add accessible row controls and localized five-save options.
- `tests/unit/party-actions.test.mjs` and existing Party unit suites: Prove
  stable token choice, delegation, GM-only rolls, empty-batch rejection, and UI
  routing without duplicate roll logic.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds the cross-generation live
  Party action gate.

## Verification

- `npm run check` passed with 93 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with `hyp3e` 4.0.3 and Foundry 14.365 with the official
  `hyp3e` dev 4.1.0 system each displayed five save categories on member and
  follower rows and pinged the exact character/NPC token centers.
- Each generation produced exactly four expected messages: member Device save,
  follower Sorcery save, individual NPC morale, and bulk NPC morale. All four
  used the existing HUD feature/action/category flags and were whispered only
  to GM users.
- After deleting the character token, both generations performed no new ping
  and emitted the localized missing-token notice.
- The first live pass reached the action checks but the diagnostic attempted a
  member click while Followers was active. Switching the diagnostic back to
  Overview corrected the test; the final production runs completed without
  errors.
