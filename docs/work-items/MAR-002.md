# MAR-002 — Build the marching-order Party UI

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The Party Sheet Marching Order tab now renders Unassigned, Front, Middle, and
Rear groups from the MAR-001 model. Member, follower, and missing tracked Actor
references are enriched into readable rows without changing the durable Party
State representation.

Every row provides native keyboard controls for moving within its current rank
or between adjacent groups. Drag and drop is an enhancement over the same
authoritative operation: dropping on a group appends the Actor, while dropping
on a row inserts it at that position. Actor links open the exact resolved
document when available.

Front, Middle, and Rear notes use local drafts with the PAR-009 conflict
policy. External Party State changes preserve unsaved text and display a stale
warning; saving submits the draft's original base revision, and an explicit
discard restores current authoritative values. The four-column layout wraps at
narrow widths without removing controls or data.

## Files changed

- `module/apps/foundation-applications.mjs`: Enriches marching rows, retains
  rank-note drafts, exposes move/open/save actions, and handles internal drops.
- `module/core/bootstrap.mjs`: Supplies the marching-order service to the Party
  Sheet application.
- `templates/party-sheet.hbs`: Renders the four groups, Actor rows, accessible
  movement controls, drop targets, notes, and stale-state feedback.
- `styles/hyp3e-utilities.css`: Adds responsive marching-order layout and row,
  control, and note styling.
- `lang/en.json`: Adds the English labels, help text, notices, and group names.
- `tests/unit/application-shell.test.mjs`: Covers context enrichment, action and
  drop delegation, stale note revisions, and discard behavior.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds connected GM/Player runtime
  coverage for controls, drag/drop, stale drafts, and responsive wrapping.
