# HUD-006 — Persist and clamp the NPC Action HUD position

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

The NPC Action HUD header is now a Pointer Events drag handle. Primary-pointer
drags preserve the grab offset, capture the active pointer when the browser
supports it, ignore buttons and other interactive controls, and save the final
`left`, `top`, and `width` values in the existing client-scoped setting.

The HUD restores that setting after a rerender or overlay recreation. Default,
stored, dragged, and resized positions are clamped to a 12-pixel viewport
margin, a normal maximum width of 704 pixels, and the available width on narrow
viewports. Malformed and off-screen values recover safely. The existing
ApplicationV2 reset menu now takes effect immediately through the shared
settings hook. Resize listeners are attached only while the overlay exists,
and the settings hook is removed when the HUD service is destroyed.

## Files changed

- `module/hud/npc-action-hud.mjs`: Adds pure default/clamping helpers,
  Pointer Events dragging, client-setting persistence, reset synchronization,
  resize handling, and listener cleanup.
- `module/settings/settings.mjs`: Publishes position-setting changes through
  the existing namespaced settings hook.
- `templates/npc-action-hud.hbs` and `styles/hyp3e-utilities.css`: Mark and
  style the header drag handle while preserving normal control interaction.
- `tests/unit/npc-action-hud-position.test.mjs`: Covers default and edge

  resize, overlay removal, and service cleanup.
- `tests/unit/settings.test.mjs`: Covers position-setting change publication.
- `tests/foundry/diagnostics/diagnostics.mjs`: Exercises the production HUD
  position lifecycle and Pointer Events in both supported Foundry generations.
