# ITM-003 — Treasury-to-character transfer operation

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The transfer service now supports the reverse authoritative workflow through
`party.transferItemFromTreasury`. The active GM resolves the currently bound
managed treasury as the only permitted source, resolves a durable world
`character` Actor as destination, verifies exact source Item and quantity
freshness, and applies the immutable ITM-001 plan.

An authorized non-GM requester must own the destination character; a GM may
transfer to any valid character. Full transfers create the character Item
before deleting its treasury source. Partial transfers create the planned
partial stack before reducing the treasury stack. Destination failure leaves
the treasury unchanged, while a later treasury failure removes the created
character Item. Rollback failure retains the explicit non-success error from
ITM-002.

Both transfer directions share one serialization queue and the same small
write/compensation executor. This prevents character-to-treasury and
treasury-to-character requests from racing around a shared Item stack while
keeping direction-specific resolution, ownership, and payload validation
explicit.

## Files changed

- `module/party/party-item-transfer.mjs`: Adds strict reverse payload handling,
  treasury source and character destination resolution, destination ownership,
  the reverse request API, and a minimally generalized shared executor.
- `tests/unit/item-transfer.test.mjs`: Adds full and partial reverse transfers,
  destination ownership, stale treasury quantity, write ordering, and source
  failure compensation.
