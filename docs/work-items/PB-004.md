# PB-004 — Verify the five-save source fields

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

Established `system.saves.<kind>.curr` as the module contract for death,
device, transformation, avoidance, and sorcery saves on both `character` and
`npc` Actors.

## Files changed

- `tests/foundry/diagnostics/diagnostics.mjs`: Added synthetic Actor and Active
  Effect runtime checks for all five saves.
- `HYP3E-UTILITIES-DESIGN.md`: Replaced the unresolved save-field discrepancy
  with the verified `curr` contract.
- `docs/compatibility-notes.md`: Recorded the source and runtime findings.

## Automated verification

- `npm run check` syntax-checks the diagnostic module.

## Manual verification

- In Foundry 14.365 with `hyp3e` 4.1.0, all five `curr` fields were numeric for
  both Actor types.
- A +2 Active Effect produced death `value` 10 and `curr` 12 on both Actor
  types.
- The `hyp3e` base Actor data model source confirms that base preparation resets
  `curr` from `value` before Active Effects apply.

## Known limitations and follow-up

- The adapter and roll planner that consume this contract are future FND-002
  and HUD-002 work.
