# HUD-007 — Debounce HUD synchronization and verify cleanup

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

High-frequency `updateActor` and `updateToken` hooks now use a trailing
50-millisecond debounce before rebuilding the NPC selection model. Repeated
updates share one promise and reset one timer. Control changes, canvas
lifecycle, create/delete hooks, and settings changes remain immediate so HUD
visibility and direct selection never feel delayed.

Destroying the controller cancels and resolves pending debounce work before
removing every hook. Repeated `start()` calls remain idempotent. The HUD
position lifecycle tests now also cover repeated start, hide/show,
destroy/restart, settings-hook cleanup, resize-listener cleanup, and render
counts.

## Files changed

- `module/hud/npc-selection.mjs`: Separates immediate and high-frequency hooks,
  implements an injectable trailing debounce, and cancels pending work during
  destruction.
- `tests/unit/npc-selection.test.mjs`: Proves burst coalescing, final-value
  publication, hook counts, pending-timer cleanup, and restart behavior.
- `tests/unit/npc-action-hud-position.test.mjs`: Proves repeated lifecycle
  cycles do not duplicate renders, settings hooks, or window listeners.
- `tests/foundry/diagnostics/diagnostics.mjs`: Exercises rapid updates and
  repeated enable/disable and service lifecycle cycles in production Foundry.

## Verification

- `npm run check` passed with 49 automated tests, syntax checks, and manifest
  validation.
- Foundry 13.351 / `hyp3e` 4.0.3 passed every HUD-007 assertion in a disposable
  data root on port 33358.
- Foundry 14.365 / official `hyp3e` dev 4.1.0 passed the same assertions in a
  disposable data root on port 33359.
- In each generation, five updates spaced 10 milliseconds apart produced one
  model notification containing the final HP value. Three enable/disable
  cycles, two destroy/restart cycles, and duplicate `start()` calls always
  retained exactly one overlay.
- Both servers were stopped and all disposable data was removed without
  modifying either installed Foundry environment or reusable world.
