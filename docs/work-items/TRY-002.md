# TRY-002 — Treasury coin and inventory views

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The Party Sheet now displays the managed treasury's native five-denomination
coin purse on the Treasure tab and its embedded physical equipment on the
Supplies tab. Coin order is CP, SP, EP, GP, and PP. Equipment rows cover
weapons, armour, shields, and ordinary gear with image, system type, quantity,
bundle, and maximum values. Empty inventory has an explicit state.

Every embedded Item remains visible. Types outside the supported physical
transfer set are clearly marked unsupported rather than silently omitted, and
a missing Item image uses `icons/svg/item-bag.svg`. Mutation controls remain
deferred to the ITM work items.

Because the managed Actor intentionally grants default None ownership, the UI
does not depend on player-side Actor visibility. An authorized Party Sheet
editor requests a revision-bound, serializable treasury snapshot through the
existing active-GM transport. The operation reuses authoritative Party Sheet
permission checks, rejects stale revisions, and exposes no document mutation.
Unauthorized users receive neither the snapshot nor lifecycle candidate data.

## Files changed

- `module/party/party-treasury.mjs`: Adds the authorized, revision-bound
  treasury snapshot operation with five normalized coins, safe Item images,
  supported categories, quantities, and preserved unsupported rows.
- `module/apps/foundation-applications.mjs`: Requests snapshots for authorized
  users and prepares deterministic coin and inventory view models.
- `templates/party-sheet.hbs`, `styles/hyp3e-utilities.css`, `lang/en.json`:
  Add responsive coin and equipment views plus empty, restricted, unavailable,
  image-fallback, and unsupported-type presentation.
- `tests/unit/party-treasury.test.mjs`: Covers all five coins, empty/missing and
  stale states, missing images, supported quantities, and unknown types.
- `tests/unit/application-shell.test.mjs`: Covers authorized player snapshots,
  local Actor invisibility, view-model preparation, and unauthorized denial.
- `tests/foundry/diagnostics/diagnostics.mjs`: Exercises the production
  snapshots and rendered tabs with connected GM/player clients and cleans all
  temporary Items and coin changes.

## Known limitations and follow-up

- These views are read-only. Item transfer entry points and transactional
  writes begin with ITM-001 through ITM-007.
- Coin distribution controls and writeback begin in Milestone 5.
- Unknown types are intentionally visible but cannot enter transfer planning.

No design-document change was required. No now-unused code remains.
