# ITM-001 — Pure item transfer planner

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Item movement now begins with a side-effect-free planner that validates both
durable Actor endpoints, source Item ownership, supported physical types,
source quantity freshness, and a positive whole transfer amount. The returned
plan records the exact source and destination Item identities, before/after
quantities, and required create, update, or delete actions. Plans and their
nested values are frozen, and planning performs no Foundry document writes.

Full transfers preserve quantity value, maximum, and bundle metadata. Partial
transfers follow hyp3e's stack-splitting behavior: the source value and maximum
are reduced, the created stack receives the transferred value as its maximum,
and bundle metadata is preserved. A merge adds both transferred value and
maximum to the selected destination stack.

Weapons, armour, and shields always create distinct destination Items.
Ordinary items merge only when a caller-supplied compatibility check explicitly
approves all relevant data; matching names alone do nothing. Multiple approved
targets are rejected as ambiguous. Synthetic Actors, same-Actor transfers,
legacy or flagged containers, unsupported Item types, stale quantities, and
source ownership mismatches fail before a plan is returned.

## Files changed

- `tests/unit/item-transfer.test.mjs`: Covers full, partial, and merged plans;

## Verification

- The targeted ITM-001 test was written first and initially failed because the
  planner module did not exist.
- `npm run check` passed with 130 automated tests, syntax checks, localization
  checks, and manifest validation.
- The quantity contract was compared to official hyp3e 4.1.0 behavior in
  `actor-sheet-v2.mjs`: splitting subtracts the transferred value from the
  source maximum, gives the new stack that transferred maximum, and combining
  stacks adds their maxima.
