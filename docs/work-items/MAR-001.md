# MAR-001 — Model marching-order groups and mutations

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Party State now has a pure marching-order view model with stable Unassigned,
Front, Middle, and Rear groups. Each group exposes ordered rows containing an
Actor UUID, rank, and zero-based position. Unassigned order follows durable
party tracking order (members, then followers), while rank order follows Party
State. Missing-but-still-tracked Actor UUIDs remain valid rows until lifecycle
cleanup removes the party reference.

Pure helpers append or insert an Actor, reposition it within a rank, move it
between ranks, swap two ranked/unassigned Actors, or remove it back to
Unassigned. Helpers normalize prior duplicates, preserve per-rank notes, and
return new marching-order data without mutating their input.

Four strict named Party operations expose placement, swap, removal, and plain
text rank-note updates through the existing authoritative store. Only tracked
world Actor UUIDs and the three approved ranks are accepted; explicit positions
must be in range at execution time.

## Files changed
