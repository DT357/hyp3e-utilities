# HRD-003 — Accessibility and Localization Pass

## Implemented outcome

Completed the keyboard, accessible-name, focus, contrast, and English
localization audit for the NPC Action HUD, Party Sheet, settings applications,
and chat output.

- Party Sheet tabs now implement a complete roving-tabindex pattern with
  Left/Right/Up/Down, Home, and End navigation. Focus returns to the active tab
  after ApplicationV2 rerendering, and the panel is programmatically related
  to its active tab.
- All module application controls receive an explicit `:focus-visible`
  outline. Marching-order drag/drop continues to have equivalent movement
  buttons for keyboard users.
- Party and treasure ProseMirror hosts and created editor elements have
  accessible names. The icon-only Actor Directory button now has an explicit
  accessible name in addition to its tooltip.
- Warning and missing-reference text inherits the active Foundry theme's text
  color and uses an accent border, avoiding a fixed low-contrast warning text
  color.
- The fixed HUD foreground/background pairs pass the WCAG AA 4.5:1 threshold.
- Runtime/template localization-key scans pass, and a mojibake separator in an
  item-transfer chat card was corrected.

## Manual checks

Foundry 14.365 with `hyp3e` 4.1.0 was run from the disposable `m3-v14`
data root in the Codex in-app Chromium browser. The rendered accessibility tree
reported:

- a named `Party Sheet` region;
- a named six-item tablist and a panel named by its active tab;
- Arrow Right moving Overview to Followers with selection, `tabindex="0"`,
  and DOM focus preserved after rerender;
- End moving focus and selection to Notes;
- a solid visible focus outline on the selected tab;
- an accessible `Party notes` rich-text editor name; and
- an accessible `Open Party Sheet` Actor Directory button name.

No browser warning/error attributable to Hyp3e Utilities occurred during the
gate. The process, port 33374, and browser tab were closed afterward.
