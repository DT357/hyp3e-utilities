# ITM-006 — Container and unsupported-item rejection

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Container classification is now a hyp3e adapter contract shared by planning,
treasury snapshots, compatibility checks, and UI entry points. Both legacy
Items of type `container` and ordinary Items with `system.isContainer` are
non-transferable, whether empty or non-empty. Items held inside a container
remain transferable individually and are detached from the source container
when their destination copy is created.

The Party Sheet marks container rows as non-transferable and explains that
their contents must be moved individually. Actor Sheet drops of a container
receive the same specific notice without opening a confirmation. Other
unsupported Item types receive a distinct unsupported-type notice. Neither
class can become draggable or expose a transfer button.

Treasury snapshots expose only `container` and `transferable` booleans in
addition to the existing Item summary; container contents remain private. The
active-GM planner independently rejects a non-empty container before any
destination or source write, so spoofed client data cannot bypass the UI.

## Files changed

- `module/adapters/hyp3e-adapter.mjs`: Adds the shared legacy/modern container
  classifier and reuses it for stack compatibility.
- `module/party/item-transfer.mjs`: Uses adapter-owned container knowledge for
  source and merge-target validation.
- `module/party/party-treasury.mjs`: Adds safe container/transferable snapshot
  flags.
- `module/party/item-transfer-ui.mjs`: Adds distinct container, unsupported
  type, and invalid-quantity rejection paths.
- `module/apps/foundation-applications.mjs`, `templates/party-sheet.hbs`, and
  `lang/en.json`: Normalize flags and present non-transferable rows and clear
  localized guidance.
- Adapter, planner/service, UI, treasury, and application unit tests now cover
  classification, snapshot output, notices, and the zero-write invariant.

## Verification

- New tests failed first on missing adapter classification, generic UI text,
  and absent snapshot flags.
- `npm run check` passed with 158 automated tests, syntax checks, localization
  checks, and manifest validation.
- The non-empty-container service fixture retained its source Item, created no
  destination Item, and recorded zero document write calls.

## Known limitations and follow-up

- Whole-container movement remains intentionally unsupported for the initial
  release; no recursive contents migration is attempted.
- ITM-007 adds success chat and the final transfer journal/recovery matrix.
- The Foundry 13/14 live workflow gate follows ITM-007.

No design-document change was required. No now-unused code remains.
