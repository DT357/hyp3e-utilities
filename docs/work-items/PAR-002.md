# PAR-002 — Implement authenticated Party Sheet mutation operations

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Party Sheet writes now have an authenticated named-operation protocol layered
over SocketLib. Every request carries a strict envelope with a request ID,
expected non-negative revision, and operation-specific payload. Unknown or
missing fields fail closed.

The GM handler derives the caller only from SocketLib's server-supplied
`this.socketdata.userId`, resolves that user from the world, and re-evaluates
the PAR-001 permission policy for every request. A bounded GM-side cache shares
in-flight results and returns the first completed result for duplicate request
IDs without re-executing the operation. No active GM, unknown operations,
authorization failures, validation failures, and execution failures return
stable structured errors.

The production API publishes registration and request methods. Actual Party
Sheet state mutations will register with this protocol in PAR-004.

## Files changed

- `module/party/party-mutation-protocol.mjs`: Adds strict request validation,
  GM-side authorization, operation registration, structured results, and
  idempotency.
- `module/socket/socket-transport.mjs`: Supports named operations registered
  before or after SocketLib initialization.
- `module/core/bootstrap.mjs`: Publishes the production mutation protocol.
- `tests/integration/socket-operations.test.mjs`: Exercises authenticated
  dispatch, spoofing, validation, authorization, no-GM handling, duplicate
  requests, and sanitized failures through the real transport/protocol pair.
- `tests/unit/socket-transport.test.mjs` and
  `tests/unit/compatibility.test.mjs`: Cover dynamic operation binding and API
  publication.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds the multi-client production
  compatibility gate.

## Verification

- `npm run check` passed with 68 automated tests, syntax checks, and manifest
  validation.
- Foundry 13.351 with `hyp3e` 4.0.3 and SocketLib 1.1.4 passed with one GM and
  one Player client.
- Foundry 14.365 with the official `hyp3e` dev 4.1.0 system and SocketLib 1.1.4
  passed with one GM and one Player client.
- Both live runs proved server-derived caller identity, authorized GM
  execution, exact-once duplicate handling, strict malformed-payload rejection,
  and an independently matching Foundry socket sender ID.

## Known limitations and follow-up

- PAR-003 defines the versioned state and revision model.
- PAR-004 attaches authoritative, serialized Party Sheet writes and stale-
  revision rejection to this protocol.
- This cache is intentionally client-session scoped and bounded to 100
  completed request IDs; persistent cross-session deduplication is outside the
  approved design.

No design-document change was required.
