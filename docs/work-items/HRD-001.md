# HRD-001 - Released-schema migration coverage

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Synthetic upgrade fixtures now cover every published Hyp3e Utilities module
version from 0.1.0 through 0.5.0. Repository history confirms that Party State
schema 1 is the only released serialized schema; schema 0 is the existing
pre-release migration fixture and remains covered separately. The new matrix
therefore tests the real historical contract instead of inventing intermediate
schema numbers.

Each release fixture upgrades without source mutation to the current complete
Party State, preserving members, followers, wages, shares, ranks, supplies,
treasure notes, rich notes, revision, and valid treasury UUIDs. The 0.1.0 case
models Foundry supplying the newly registered current default because that
release predated Party State persistence.

Treasury upgrade coverage mirrors the actual release history. Versions before
the managed treasury create and bind exactly one flagged `treasure` Actor.
Version 0.4.0 models an exported/imported flagged treasury with a changed Actor
ID and proves flag-based rebind. Version 0.5.0 retains an already valid binding
without creating or deleting an Actor. Existing tests continue to cover
missing configured Actors, duplicate candidates, explicit selection, and
schema-0 active-GM persistence.

## Files changed

- `tests/fixtures/released-module-states.mjs`: Add minimal synthetic Party
  State and treasury fixtures for module versions 0.1.0–0.5.0.
- `tests/unit/release-migrations.test.mjs`: Run every release fixture through
  current Party State normalization and managed treasury initialization.
- `IMPLEMENTATION-PLAN.md`: Mark HRD-001 complete.

No production migration was added because all published states already use
schema 1 and the existing treasury flag/UUID contract. Adding a fictitious
schema version would create an unsupported format rather than harden upgrades.

## Verification

- The release-matrix test failed before its fixture catalog existed.
- `npm run check` passes with 220 tests, syntax checks, localization checks,
  and manifest validation.

## Known limitations and follow-up

- Upgrade tests intentionally use minimal synthetic documents and contain no
  personal world data.
- A future Party State shape change must increment
  `PARTY_STATE_SCHEMA_VERSION` and add its released fixture to this matrix.

No design-document change was required. No now-unused code remains.
