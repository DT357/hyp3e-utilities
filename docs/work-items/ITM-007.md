# ITM-007 - Transfer audit and recovery hardening

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Every successful character/treasury transfer now creates one public audit chat
card after both inventory writes complete. The escaped card records the Item,
quantity, source, destination, requester, and whether the destination was a new
Item or a merged stack. Stable module flags retain the exact source and
destination Actor UUIDs, source Item UUID, requester user ID, quantity, and
merge state.

Audit creation is deliberately post-commit. If chat creation fails, the
already-consistent inventory remains committed, the operation returns
`auditCreated: false`, and the requester receives a localized warning rather
than a false transfer failure. No audit is attempted for a failed document
write.

The recovery matrix covers destination creation and merge updates, source
updates and deletion, reverse-direction writes, successful compensation, and
explicit compensation failure. Destination-first writes ensure an initial
failure leaves the source untouched; a later source failure restores or
removes the destination before returning a non-success result.

The live gate also identified and corrected the Actor Sheet lifecycle hook:
the supported hyp3e sheets inherit `ActorSheetV2`, so transfer controls now
register on `renderActorSheetV2` in both supported Foundry generations.

- `tests/foundry/diagnostics/diagnostics.mjs`: Add repeatable GM/Player

  cleanup checks.

## Verification

- New audit, warning, and `ActorSheetV2` hook tests failed before their
  implementations were added.
- `npm run check` passed with 164 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with hyp3e 4.0.3 passed the connected GM/Player transfer
  matrix on port 33373.
- Foundry 14.365 with hyp3e 4.1.0 passed the same matrix on port 33374.
- Both live runs created public audit cards, conserved Item quantities in both
  directions, rendered enabled Actor Sheet and Party Sheet controls, matched
  raw Player sender identity, reported no diagnostic errors, and removed all
  Item-transfer fixtures and audit cards.
- No transfer-related warning or error remained in any of the four browser
  clients. Both disposable servers were stopped after the gate.

## Known limitations and follow-up

- A persistent compensation failure is reported as `itemTransferRollbackFailed`
  for explicit GM reconciliation; it is never presented as a successful or
  safely restored transfer.
- Transfer audits are intentionally public and informational. Inventory state,
  not chat history, remains authoritative.
- The separate 0.4.0 package/version regression gate closes Milestone 4.

No design-document change was required. No now-unused code remains.
