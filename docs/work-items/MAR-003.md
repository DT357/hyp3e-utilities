# MAR-003 — Publish the Party marching-order chat report

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The Marching Order tab now provides a localized **Post Saved Order to Chat**
action. It creates one public chat card from the authoritative Party State,
rather than from unsaved local note drafts. The card always lists Front,
Middle, and Rear in that order, preserves Actor order within each rank, shows
an explicit Empty row for an unoccupied rank, includes non-empty rank notes,
and records the source Party State revision in module flags.

Actor UUIDs, resolved Actor names, rank notes, and localized labels are escaped
before HTML assembly. Missing tracked Actors therefore remain visible by their
escaped UUID without preventing the report. The public message has no whisper
recipients and can be observed by connected Players.

## Files changed

- `module/chat/chat-cards.mjs`: Validates and renders ordered public
  marching-order cards and creates the flagged Foundry chat message.
- `module/apps/foundation-applications.mjs`: Builds the report from saved state,
  resolves current Actor names, and exposes the Party Sheet action.
- `module/core/bootstrap.mjs`: Supplies the shared chat-card service to the
  Party Sheet application.
- `templates/party-sheet.hbs`: Adds the localized report action.
- `styles/hyp3e-utilities.css`: Styles rank sections, lists, and empty rows.
- `lang/en.json`: Adds report actions, errors, title, ranks, note, and empty-row
  English strings.
- `tests/unit/chat-cards.test.mjs`: Covers public visibility, rank and Actor
  order, empty ranks, escaping, flags, and revision.
- `tests/unit/application-shell.test.mjs`: Proves the application reports saved
  state rather than an unsaved rank-note draft.
- `tests/unit/compatibility.test.mjs`: Confirms public API publication.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds GM creation and connected
  Player visibility checks in both supported Foundry generations.

## Verification

- `npm run check` passed with 105 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with `hyp3e` 4.0.3 passed report creation, ordering, empty-rank,
  escaping, public visibility, revision-flag, and Player-observation checks.
- Foundry 14.365 with official `hyp3e` dev 4.1.0 passed the same matrix.
- Manual rendered-card inspection confirmed the hostile note appeared only as
  readable text and the three-rank report remained clear.

## Known limitations and follow-up

- Unassigned Actors are intentionally excluded because the report represents
  the active three-rank formation.
- The action labels itself as the saved order; unsaved note drafts remain local
  until explicitly saved or discarded.
- Later distribution and transfer reports will reuse the same escaped public
  chat conventions in their owning work items.

No design-document change was required. No now-unused code remains.
