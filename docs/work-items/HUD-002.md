# HUD-002 — Implement save and morale roll planning

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

Added immutable save and morale batch planners using only the `hyp3e` adapter.
Save plans require one of the five explicit categories, use the prepared
`system.saves.<kind>.curr` target, and succeed at or above that value. Morale
plans use numeric `system.morale` and succeed at or below it. Missing or invalid
targets are skipped with explicit reasons.

Corrected optional adapter parsing so `null`, blank, and invalid save, morale,
or loyalty values remain `null` instead of being converted to zero.

## Files changed

- `module/hud/npc-rolls.mjs`: Implements save/morale planning and result
  evaluation.
- `module/adapters/hyp3e-adapter.mjs`: Preserves missing optional rule values.
- `module/core/bootstrap.mjs`: Publishes the planners on the module API.
- `tests/unit/npc-rolls.test.mjs`: Covers all five saves, prepared modifiers,
  categories, numeric strings, zero morale, missing data, and success/failure.
- `tests/unit/hyp3e-adapter.test.mjs`: Locks optional-value behavior.
- `tests/foundry/diagnostics/diagnostics.mjs`: Exercises live prepared targets.

## Verification

- `npm run check` passed with 34 automated tests.
- Both supported Foundry environments used all five current save targets,
  retained a +2 Active Effect adjustment, passed save/morale boundary checks,
  and skipped missing targets without browser warnings or errors.
