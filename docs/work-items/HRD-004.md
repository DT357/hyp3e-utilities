# HRD-004 — Performance and Hook-Lifecycle Pass

## Implemented outcome

Completed the large-data, rapid-update, scene-transition, and repeated
application-lifecycle hardening pass.

- Party Sheet context preparation now requests the managed-treasury snapshot
  only for Followers, Supplies, and Treasure, the tabs which consume it.
- Party notes are enriched only on Notes, while gems and miscellaneous
  treasure notes are enriched only on Treasure. Other tabs no longer pay the
  rich-text enrichment cost.
- Stress coverage exercises 800 tracked party Actors, 2,000 treasury Items,
  1,000 rapid token/Actor update events, 50 canvas teardown/ready cycles, and
  100 repeated lifecycle cycles for the NPC Action HUD, Party Sheet, and Actor
  Sheet item-transfer controller.
- Rapid selection events continue to coalesce into one scheduled refresh, and
  every registered hook, subscription, and window listener is released.

## Automated checks

- Focused application, transfer-UI, and performance/lifecycle suite: 35 tests
  passed.
- Complete `npm run check`: 234 tests passed; module and diagnostic syntax
  checks and manifest validation passed.
- Measured stress runtimes on the development host were approximately 18 ms
  for the 800-Actor party model, 2 ms for the 2,000-Item treasury snapshot,
  194 ms for 1,000 rapid updates plus 50 scene cycles, and 2 ms or less for
  each 100-cycle application/controller lifecycle test. Each remains below the
  deliberately generous 1,000 ms regression budget.

## Manual checks

Foundry 14.365 with `hyp3e` 4.1.0 was run from the disposable `m3-v14` data
root in the Codex in-app Chromium browser.

- The Party Sheet was opened and closed 20 consecutive times.
- The active tab was rotated through Overview, Followers, Marching Order,
  Supplies, Treasure, and Notes during those cycles.
- Every open produced exactly one Party Sheet window and every close removed
  it.
- The browser reported no warning or error entries during the lifecycle run.

The browser tab and port 33374 were closed afterward.

## Known limitations and follow-up

- The 1,000 ms thresholds are regression tripwires, not user-interface service
  level guarantees; absolute timing varies by host.
- HRD-005 repeats core lifecycle behavior in the clean Foundry 13/14 release
  matrix.

No design-document change was required.
