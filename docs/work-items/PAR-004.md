# PAR-004 — Implement the GM-authoritative Party Sheet store

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Party Sheet state now has one production store that publishes normalized local
reads and accepts writes only through module-owned named mutations registered
with the PAR-002 protocol. Every mutation executes on the current active GM,
rechecks active-GM authority immediately before persistence, and enters one
serialized queue.

At the queue head, the store re-reads and normalizes world state, compares the
request's expected revision, and rejects stale work before invoking its
mutator. Successful work advances the revision exactly once, writes canonical
state, and returns both the prior revision and fresh state. Stale results
include fresh state for rerender or an explicit retry.

If a setting write fails after partially applying, the store re-reads the
setting and restores the exact prior snapshot. It distinguishes a verified
rollback from a failed or unverifiable compensation. Schema normalization and
migration persist without a revision bump only from the active GM. The world
setting now publishes a namespaced Party State update hook.

## Files changed

- `module/party/party-store.mjs`: Adds normalized reads, active-GM migration,
  named mutations, serialized writes, stale-revision responses, revision
  advancement, and compensation.
- `module/party/party-mutation-protocol.mjs`: Adds stable store error codes.
- `module/core/bootstrap.mjs`: Publishes and initializes the production store.
- `module/core/constants.mjs` and `module/settings/settings.mjs`: Add the
  namespaced Party State update hook.
- `tests/integration/party-store.test.mjs`: Covers concurrency, stale state,
  successful rollback, failed rollback, mutator failure, active-GM changes,
  and migration authority through the real protocol/transport/store stack.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds the two-client production
  concurrency and retry gate.
- `tests/unit/compatibility.test.mjs` and `tests/unit/settings.test.mjs`: Cover
  API publication and setting-hook emission.

## Verification

- `npm run check` passed with 79 automated tests, syntax checks, and manifest
  validation.
- Foundry 13.351 with `hyp3e` 4.0.3 and SocketLib 1.1.4 passed with one GM and
  one Player client.
- Foundry 14.365 with the official `hyp3e` dev 4.1.0 system and SocketLib 1.1.4
  passed with one GM and one Player client.
- In both live runs, two Player writes started at revision 0. Exactly one
  committed revision 1; the other returned `staleRevision` with fresh state;
  its explicit retry committed revision 2. The Player and GM both observed the
  same two-member revision-2 state, and the raw Foundry sender matched the
  Player.

  operation.
- Cross-document transaction journaling and recovery belong to DST-001; this
  item covers the single Party State setting and its compensation boundary.
