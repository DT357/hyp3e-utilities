# ITM-002 — Character-to-treasury transfer operation

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Authorized Party Sheet editors can now request a revision-bound physical Item
transfer from a durable world `character` Actor to the configured managed
treasury. The authenticated active-GM operation resolves every live document,
requires a non-GM requester to own the source character, and builds a fresh
ITM-001 plan using the expected source quantity before any write occurs. GMs
may transfer from any valid source character.

Executions are serialized. The destination create occurs first; full transfers
then delete the source Item and partial transfers update its stack. Newly
created treasury Items receive a new embedded identity, the planned quantity
metadata, and a blank `containerId` because treasure inventory must remain
stand-alone. If the destination write fails, the source is untouched. If the
source write fails, the created destination Item is deleted. A failed
compensation has its own error and never reports success.

The operation is registered as `party.transferItemToTreasury` through the
existing mutation protocol, so strict payload validation, trusted SocketLib
caller identity, Party Sheet edit authorization, active-GM routing, request-ID
idempotency, and sanitized errors remain shared infrastructure. Inventory
writes do not alter party-state revision; the revision is a confirmation
boundary, while the exact source quantity prevents replay against changed Item
state.

## Files changed

- `module/party/party-item-transfer.mjs`: Adds strict request validation,
  authoritative source/treasury resolution, source ownership checks, serialized
  planning, destination-first writes, compensation, and the public request API.
- `module/adapters/hyp3e-adapter.mjs`: Adds the transfer-create update contract,
  including stand-alone `containerId` handling.
- `module/core/bootstrap.mjs`: Registers and exposes the transfer service.
- `tests/unit/item-transfer.test.mjs`: Covers full and partial operations,
  Player ownership, GM override, party/source staleness, serialization, strict
  payloads, destination failure, source failure, and rollback failure.
- `tests/unit/hyp3e-adapter.test.mjs`: Covers the transfer-create field mapping.

## Verification

  checks, and manifest validation.

  Actors and never trusts client-supplied destination identity.
