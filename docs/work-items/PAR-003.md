# PAR-003 — Implement the versioned Party Sheet state model

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Party Sheet metadata now has one canonical, JSON-safe schema at version 1 with
a non-negative monotonic revision. The schema centralizes independent defaults
for treasury binding, members, followers, wages, shares, marching order,
supplies, treasure notes, and shared notes.

Normalization is pure and deterministic. It fills missing fields, rejects
unknown schema fields, retains only durable world Actor UUIDs, deduplicates
references, prevents an Actor from being both a member and follower, limits
wages to non-negative whole GP values, rounds shares to non-negative quarter
increments, prunes metadata for untracked Actors, and ensures marching-order
Actors are tracked and assigned to at most one rank. It does not mutate input
or generate IDs.

An explicit schema-0 migration adds the revision field and advances to schema
1. Future schemas fail with a clear error. Revision advancement normalizes the
state, increments exactly once, and rejects unsafe integer overflow.

## Files changed

- `module/party/party-state.mjs`: Adds defaults, strict schema handling,
  normalization, migration, and revision advancement.
- `module/settings/settings.mjs`: Uses and re-exports the canonical default
  factory rather than maintaining a duplicate schema.
- `tests/unit/party-state.test.mjs`: Covers canonical round trips, missing and
  unknown fields, normalization invariants, old and future versions, input
  immutability, and revision advancement.
