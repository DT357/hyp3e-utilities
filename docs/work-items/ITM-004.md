# ITM-004 — Quantity and merge semantics

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

Both item-transfer directions now use a conservative hyp3e ordinary-item
compatibility contract. Only two non-container Items of type `item` can merge,
and only when their name, image, flags, effects, bundle size, and every known or
future intrinsic `system` field match. Weapons, armour, and shields never
merge.

Stack value and maximum are intentionally excluded because they are the values
being combined. Actor-placement fields (`containerId`, `location`, `equipped`,
and `inStorage`) are excluded because the destination copy is stand-alone and
may be held differently. Name alone is therefore insufficient, while an
unrecognized upstream intrinsic-field difference safely prevents a merge.

Full merges add the complete source value and maximum to the destination.
Partial merges add the transferred partition, reduce the source by that same
partition, and preserve bundle metadata. Nullable maximum and bundle fields
remain nullable. The service updates a compatible destination stack instead of
creating an Item and restores its exact prior quantity if the source write
fails.

## Files changed

- `module/adapters/hyp3e-adapter.mjs`: Adds canonical, non-mutating hyp3e stack
  profiles and the conservative ordinary-item compatibility decision.
- `module/party/party-item-transfer.mjs`: Enables the adapter matcher in both
  authoritative directions while preserving test injection.
- `tests/unit/hyp3e-adapter.test.mjs`: Covers compatible placement/quantity
  differences; name, image, cost, bundle, flags, effects, and unknown-field
  mismatches; containers; and all three never-stack equipment types.
- `tests/unit/item-transfer.test.mjs`: Covers full merge conservation, nullable
  metadata, live service merges, and merge rollback.

## Verification

- Compatibility, conservation, and service-merge tests were added first and
  failed before the matcher was implemented and enabled.
- `npm run check` passed with 147 automated tests, syntax checks, localization
  checks, and manifest validation.
- Fixtures cover `weapon`, `armor`, `shield`, and `item` plus numeric and
  nullable quantity metadata.

## Known limitations and follow-up

- Deliberately conservative differences may create two safe stacks where a GM
  might consider them equivalent; this is preferable to merging Items that
  would lose distinct data.
- ITM-005 adds UI entry points and confirmation. ITM-006 presents explicit
  container/unsupported rejection. ITM-007 completes audit and recovery gates.
- The Foundry 13/14 live transfer matrix remains the M4 exit gate.

No design-document change was required. No now-unused code remains.
