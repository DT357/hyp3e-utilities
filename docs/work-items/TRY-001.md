# TRY-001 — Managed Party Treasury lifecycle

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The active GM now owns a production Party Treasury lifecycle service. A new
world creates one `treasure` Actor named `Party Treasury`, marks it with the
module's durable treasury flag, places it in a top-level `Hyp3e Utilities`
Actor folder when possible, grants the active GM Owner permission, leaves
default ownership at None, and binds its world Actor UUID into Party State.

The binding remains stable across Actor renames. A single flagged Actor from
an imported world is rebound automatically by its flag rather than its name or
local ID. Deleting a configured treasury does not silently create a
replacement: the Treasure tab reports the missing resource and gives GMs an
explicit Recreate action. Multiple flagged Actors are preserved, warned about,
and presented for explicit GM selection.

All lifecycle mutations travel through the existing authoritative Party
mutation protocol. Only a GM may bind a treasury and only the active GM client
may create one. Authorized non-GM Party Sheet editors receive read-only status
and no lifecycle controls.

## Verification

- `npm run check` passed with 119 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with `hyp3e` 4.0.3 passed the complete connected GM/player
  regression and every TRY-001 lifecycle assertion.
- Foundry 14.365 with official `hyp3e` dev 4.1.0 passed the same matrix.
- Both generations proved rename stability, explicit missing-Actor recovery,
  export/import flag recovery, duplicate preservation and explicit selection,
  folder/flag/ownership contracts, and non-GM lifecycle denial. Raw Foundry
  sender IDs matched the connected Players and no diagnostic errors remained.

## Known limitations and follow-up

- The Treasure tab does not yet display the Actor's coins or physical items;
  those views begin in TRY-002.
- Treasury Actors intentionally default to no player ownership. Later transfer
  operations will execute authoritatively rather than exposing unrestricted
  Actor editing.
- A folder-creation failure is logged and treasury creation continues at the
  world root so folder organization cannot block recovery.

No design-document change was required. No now-unused code remains.
