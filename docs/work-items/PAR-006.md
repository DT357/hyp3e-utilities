# PAR-006 — Implement Overview party-member management

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The Party Sheet Overview is now a working character-member view. Its
GM-authoritative operations accept only durable world `character` Actors,
require non-GM requesters to own the Actor, reject NPCs and synthetic token
Actors, and prevent an Actor from being tracked twice. Removing a member clears
only its member share and marching-order metadata; follower data and the Actor
document remain untouched.

Members can be added from the active Actor Directory selection, controlled
linked character tokens, or an Actor drag/drop. The Actor Directory also has a
localized, idempotent Open Party Sheet button. The Overview displays portrait,
name, race, class, level, HP, AC, DR, movement, and current share, and its name
link opens the resolved world Actor sheet.

Unresolved references remain visible as missing entries with an explicit
cleanup action. This preserves evidence of deleted Actors until the authorized
user removes the reference; automatic pruning remains assigned to PAR-010.

## Files changed

- `module/party/party-members.mjs`: Adds strict member payload validation,
  durable Actor resolution, display rows, and authoritative add/remove
  mutations.
- `module/apps/foundation-applications.mjs`: Adds Overview context and actions,
  all three member-add entry points, Actor links, cleanup, and the Actor
  Directory button.
- `module/core/bootstrap.mjs`: Publishes the member service and binds the Actor
  Directory lifecycle hook without changing the applications API shape.
- `templates/party-sheet.hbs`, `styles/hyp3e-utilities.css`, and
  `lang/en.json`: Add the localized responsive Overview interface.
- `tests/unit/party-members.test.mjs`,
  `tests/unit/application-shell.test.mjs`, and
  `tests/unit/compatibility.test.mjs`: Cover membership rules, ownership,
  metadata cleanup, row stability, entry points, and API publication.
- `tests/foundry/diagnostics/diagnostics.mjs`: Adds the cross-generation live
  Overview acceptance gate.

## Verification

- `npm run check` passed with 84 automated tests, syntax checks, localization
  checks, and manifest validation.
- Foundry 13.351 with `hyp3e` 4.0.3 and Foundry 14.365 with the official
  `hyp3e` dev 4.1.0 system both passed every PAR-006 runtime assertion.
- Both generations rendered the Actor Directory opener and the localized empty
  Overview with selected-Actor, controlled-character, and drag/drop guidance.
- The first live run exposed an enumerable non-Application helper in the public
  applications collection. Moving it to a static Party Sheet method preserved
  the established applications API; the corrected rerun completed with no
  diagnostic errors.
