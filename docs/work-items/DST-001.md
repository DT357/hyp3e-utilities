# DST-001 - Shared distribution transaction behavior

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

XP awards, five-denomination coin distribution, and GP wage settlement now use
one small transaction primitive for revision/fingerprint preflight, ordered
document writes, reverse-order compensation, audit creation, and explicit
failure classification. Domain failures such as a recipient becoming invalid
survive compensation unchanged; infrastructure write failures use each
operation's public write-failure code.

Rollback attempts every registered compensation even if one restoration fails,
then returns the operation-specific rollback-failure code. A final chat audit
runs only after every document write succeeds. Audit failure restores all
registered writes before returning an audit error; a failed restoration takes
precedence so the caller is never told the state is safe when it is not.

Idempotency remains at the authoritative Party mutation boundary, keyed by
requester and stable request ID. Production-protocol integration tests now
exercise in-flight and completed duplicates for XP, coin, and wage operations,
proving each document write and chat report occurs exactly once.

## Known limitations and follow-up

- Document updates are assumed atomic at the Foundry document boundary. If a
  document implementation mutates and then rejects the same update promise,
  that failed write cannot safely register a compensating snapshot.
- The Milestone 5 live gate will validate the complete distribution workflows
  on Foundry 13 and 14 with disposable fixtures.

No design-document change was required. The three private per-service rollback
implementations became unused and were removed during this refactor.
