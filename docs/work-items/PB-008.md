# PB-008 — Prove SocketLib caller authentication

Status: `DONE`

Completed: 2026-08-14

## Implemented outcome

Proved that SocketLib v1.1.4 supplies the actual requesting Foundry user ID to
a GM-side handler independently of caller-controlled payload fields. This
unblocks a GM-authoritative, named-operation transport for authorized player
edits.

## Files changed

- `tests/foundry/diagnostics/diagnostics.mjs`: Added a SocketLib GM handler,
  spoofed-identity player request, and independent raw Foundry sender check.
- `tests/foundry/diagnostics/module.json`: Declares the test-only SocketLib and
  Hyp3e Utilities requirements.
- `HYP3E-UTILITIES-DESIGN.md`: Records the trusted caller-identity source and
  remaining production transport responsibilities.
- `docs/compatibility-notes.md`: Records the runtime and source evidence.

## Automated verification

- `npm run check` syntax-checks the diagnostic module.

## Manual verification

- A Player sent the GM's user ID as a claimed payload identity.
- The GM handler received the Player's real ID as `this.socketdata.userId` and
  executed on the active GM client.
- Foundry's raw socket callback independently reported the same Player sender
  ID.
- The same request succeeded after reconnect; the no-GM interval produced
  SocketLib's explicit no-active-GM error.
- SocketLib source constructs `socketdata.userId` from Foundry's socket
  `senderId`, not from the request payload.
