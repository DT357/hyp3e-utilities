# XP-003 - Transactional XP awards

Status: `DONE`

Completed: 2026-08-15

## Implemented outcome

The GM can now confirm a current XP preview. The request carries the complete
numeric preview fingerprint and its Party Sheet revision to the active GM.
Preflight recomputes the allocation from current state and current Actor XP
bonuses; a changed revision, recipient, share, type, bonus, selection, or total
rejects the request before an Actor write.

Character XP totals are updated sequentially through the hyp3e adapter. NPC
allocations remain in the divisor and final report but never call `Actor.update`
and never touch `npc.system.xp`. A journal records each completed character
write and restores it in reverse order if a later write or the required chat
audit fails. Compensation failure has its own explicit error and is never
reported as safe or successful.

One escaped public chat card reports the pool, shares, remainder, requester,
and every included recipient's base, signed adjustment, final allocation, and
character/NPC writeback status. Stable flags retain request, requester,
revision, and total XP identifiers. A preview reuses one request ID across
repeat confirmation attempts so the mutation protocol can suppress duplicate
execution.
